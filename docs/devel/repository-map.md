# Repository Map and Editing Boundaries

The build runs in five steps: fetch pinned sources and inputs, prepare the platform, compile, verify artifacts, and package. Some files in the repository are generated by scripts; the table below marks which paths can be edited directly and which will be overwritten on the next build.

## Directory Purpose

| Directory / File | Source | Purpose and How to Edit |
| --- | --- | --- |
| `uefi/core/` | Hand-written source | ProductCore, USB/UFS, input, and shared protocol sources; edit directly |
| `uefi/components/` | Hand-written source | Feature-scoped components (`os-boot`, `linux-loader`, `product-handoff`, etc.); edit directly |
| `uefi/handoff/` | Hand-written source | Front-end selector, BootShim, and cold-boot early memory code; edit directly |
| `uefi/platforms/pianoPkg/` | Hand-written template | Base platform description and component references; check the generator tools before editing |
| `uefi/platforms/pianoProbePkg/` | Hand-written template | Diagnostic platform template, also used as the baseline for product assembly |
| `uefi/platforms/pianoProductPkg/` | Script-generated | Temporary platform for product builds; untracked—do not hand-edit files inside |
| `config/` | Hand-written config | Kernel version, firmware manifest, distribution dependencies, and related configs; edit directly |
| `linux/configs/`, `linux/dts/` | Hand-written config | Kernel configuration fragments and Device Tree overlays; edit directly |
| `linux/bsp/`, `linux/rootfs/`, `linux/desktops/` | Hand-written recipes | Multi-distribution support, rootfs assembly, and desktop environment configuration; edit directly |
| `tools/` | Hand-written scripts | Build, packaging, and verification scripts; edit directly |
| `tests/` | Hand-written tests | Host-side Python and native C tests; edit directly |
| `upstream/` | Submodules | Upstream sources pinned to fixed commits; do not edit directly—express changes through `patches/` |
| `vendor/piano/` | Input files | Board DTB, xbl-config DTB, and stock PE binaries, verified by `tools/piano_vendor_inputs.py` |
| `build/firmware-workspace/` | Script-generated | Temporary build copy for product firmware; untracked |
| `build/`, `artifacts/` | Script-generated | Build outputs and intermediate files; untracked |
| `docs/` | Hand-written docs | User and developer documentation; edit directly |

## How Product Firmware Is Produced

`./build.sh uefi` runs the following five steps:

1. `tools/firmware_workspace.py` creates an isolated copy in `build/firmware-workspace/` without modifying submodules under `upstream/`.
2. `tools/apply_firmware_patches.py` applies the patches from `patches/firmware/series.json` inside the workspace copy.
3. `tools/prepare_product_handoff.py`, `prepare_product_pump.py`, `prepare_product_ui.py`, `prepare_nv_runtime_guard.py`, and `build_simpleinit.sh` install runtime hooks and menus.
4. `tools/prepare_product.py` uses `pianoProbePkg` as the baseline, assembles the ProductCore INF, DSC/FDF, and components from `uefi/components/`, and writes `pianoProductPkg` into the workspace copy.
5. `tools/build_stage0.sh product` compiles the firmware, `tools/build_integrity.py` verifies inputs and outputs, and `tools/package_product.py` completes final packaging.

To modify functionality, edit source files in `uefi/core/` and `uefi/components/`; to modify packaging or dependencies, edit the corresponding tools.
