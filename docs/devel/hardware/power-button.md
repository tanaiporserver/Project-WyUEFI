# Power Button, Lid Close, and Sleep

## Responsibilities

The kernel reports the power button (`KEY_POWER`) and cover switch (`SW_LID`), and handles panel resume and system wakeup. The distribution's udev tags both the button and switch with `power-switch`, and `logind` consumes those events. While a GNOME session is active, power button behavior is controlled by the Power section in GNOME Settings; without a desktop inhibitor, `logind` configuration applies. Lid close behavior likewise follows the distribution policy, including external display handling and application suspend inhibitors.

GNOME uses the chassis type reported by `systemd-hostnamed` to distinguish tablets from virtual machines. The image keeps the standard `CHASSIS=tablet` setting, without a custom long-press shutdown menu or separate backlight control.

## Default Settings

The [standard dconf configuration](../../../linux/desktops/gnome/overlay/etc/dconf/db/local.d/00-power) sets idle screen blanking to 2 minutes, automatic suspend on battery to 5 minutes, and automatic suspend on AC power to 10 minutes. Keyboard backlight defaults to 80%, and subsequent sessions preserve the user's saved brightness. Users can change these preferences in System Settings.

On startup, the GSD power manager reads GNOME's existing screen-lock state before configuring idle timers and display power. If the session is already locked, the screen stays off; if the query fails, the previous display power state is preserved so restarting the service does not light up the backlight behind a black screen. Normal input continues to use GNOME's standard wake and re-blank flow without adding a backlight polling service.

Both Debian GNOME and KDE images allow suspend-to-RAM (`mem/deep`). Disk hibernate, hybrid sleep, and suspend-then-hibernate remain disabled.

## Kernel Adaptations

- Display PLL save/restore, dual-DSI shutdown order, DPU stop sequence, and PHY runtime clocks are handled by `patches/linux/7.3/0002-display.patch`.
- `0029-sm8750-pcie-active-wakeup.patch` keeps the PCIe power domain active across the wakeup path so Wi-Fi PCI configuration space remains readable after resume.
- `0030-soc-qcom-smp2p-sleepstate.patch` notifies stock firmware of the AP sleep state; it does not by itself resolve all ADSP resume issues.
- `0032-asoc-q6apm-clear-global-on-remove.patch` fixes global object lifetime during ADSP restarts.
- `0033-fastrpc-freeze-inflight-invoke.patch` handles in-flight FastRPC calls during sleep.

RTC and power-button wakeup are working on device. The kernel rejects suspend when current charging protection cannot continue monitoring across suspend. To verify the full path, unplug the charger first, then test entering suspend via the power button and via lid close, waking by opening the cover or pressing the button, and verifying the lock screen after resume. When debugging sleep, judge results using the same boot ID, resume errors, and touchscreen/network state.

## Upgrading from Older Images

Installing or upgrading `piano-device-config` cleans up unmodified helper scripts and configs generated by older images while preserving files edited by the user or owned by other packages. Existing idle timeout and lock-screen defaults remain unchanged. Reboot after upgrading so the system reloads udev, `logind`, and GNOME settings. Freshly installed images no longer include the legacy helpers.

Older Debian images may still have regular suspend masked. Check with `systemctl is-enabled sleep.target suspend.target`; if either shows `masked` and you confirm it came from the image defaults rather than your own override, unmask both:

```sh
sudo systemctl unmask sleep.target
sudo systemctl unmask suspend.target
```

Package upgrades do not unmask these two targets automatically because they cannot distinguish older image defaults from an intentional administrator override.
