# Stock Piano Refresh Rate Switching

This note cross-references MiCode display driver commit `aa06fd1757c28dce96fbe4e04d4530ec21b52aac` with the final Android DT from the same device, without assuming that branches present in the generic driver actually run on this device.

## Final DT Configuration

The stock boot arguments select `qcom,mdss_dsi_p81_35_02_0b_dualdsi_dsc_vid`. This node enables `mi,video-mode-multi-timing` and `qcom,mdss-dsi-pan-enable-dynamic-fps`, using `dfps_immediate_porch_mode_vfp` as the update method.

The three base timing groups are 120, 144, and 90 Hz. The 120 Hz group allows 120 and 60 Hz; the 90 Hz group also allows 50, 48, and 30 Hz. Lower refresh rates are generated by increasing the vertical front porch rather than reinitializing the panel for every refresh rate. All three groups configure a DSI bit clock of 1,197,500,000 Hz.

The CSOT timing-switch command selects page 0x10, unlocks, and then writes B2 followed by B3:

| Timing Group | B2 | B3 |
| --- | --- | --- |
| 120 Hz (including 60 Hz) | 0x91 | 0x40 |
| 144 Hz | 0x00 | 0x00 |
| 90 Hz | 0x00 | 0x80 |

`qcom,mdss-dsi-timing-switch-video-command-state` is `dsi_hs_mode`. BOE uses the reverse command order, so the CSOT order cannot be applied to all panels.

## Code Paths

- `dsi_display_dfps_update()` in [dsi_display.c](https://github.com/MiCode/vendor_opensource_display-drivers/blob/aa06fd1757c28dce96fbe4e04d4530ec21b52aac/msm/dsi/dsi_display.c#L5433) first updates timings asynchronously on the clock-master controller, then updates the remaining controllers. The DFPS/VRR path configures timing double buffering and updates host config; it is not equivalent to tearing down all display resources and restarting them.
- `dsi_panel_post_enable()` in [dsi_panel.c](https://github.com/MiCode/vendor_opensource_display-drivers/blob/aa06fd1757c28dce96fbe4e04d4530ec21b52aac/msm/dsi/dsi_panel.c#L6594) sends `DSI_CMD_SET_TIMING_VIDEO_SWITCH` for P81.
- The VRR commit flow in [sde_encoder.c](https://github.com/MiCode/vendor_opensource_display-drivers/blob/aa06fd1757c28dce96fbe4e04d4530ec21b52aac/msm/sde/sde_encoder.c#L7075) waits for video to enter the active region, commits the new display data, and then sends that command for P81. Exiting 60 Hz to a non-120 Hz mode also includes a separate `DSI_CMD_SET_DISP_PEN_CLEAR` step and waits for the next vertical sync.

## Linux Comparison

Linux currently performs a full modeset, shutting down and re-preparing the panel and display link. After aligning the CSOT B2/B3 order with stock and resending the timing command in HS mode during panel enable, 120 Hz booted normally and the command returned success, but switching to 60 Hz still resulted in a gray screen. Simply resending the command therefore does not reproduce the full stock dynamic switching flow. This experiment was not added to the release patch series, and the device was restored to the standard module.

The next step is an on-device Android runtime capture to confirm the active DFPS/VRR branch and compare commits, clocks, and timing registers across the master and slave controllers. Linux should implement fixed refresh-rate switching through the standard DRM modeset interface rather than merely adding a refresh-rate toggle.

## 2026-10-13 On-Device Runtime Capture

`sde:sde_evtlog` was enabled in a separate ftrace instance and then disabled and removed afterward without modifying Android's existing tracing instance. The trace captured `dsi_display_dfps_update` entry and exit, and `dsi_display_set_mode_sub` reported mode flags `0x10`. This proves the device uses the dynamic timing update branch rather than leaving the source branch as speculation.

Both capture rounds requested 60 Hz, but the current DRM state read back 50 Hz rather than 60 Hz. The first round also mistakenly used landscape dimensions; in the second round, after setting the preference using the 2136×3200 dimensions registered by DisplayManager, the state was still 50 Hz. An exact 120→60→120 comparison was therefore not yet completed, and requested command values must not be reported as the observed mode.

The 50 Hz timing is 807067 kHz, with a horizontal total of 3882 and a vertical total of 4158. Captured DSI byte clock is 149687500 Hz and pixel clock is 159666666 Hz. The stock static-screen refresh-rate policy must be distinguished from hardware switching. Follow-up captures should observe the active mode and cover a steady 60 Hz rather than relying solely on settings.

Temporary peak/min refresh rate settings, user display mode preferences, and screen-off timeout were restored, and the device was returned to Linux via the native request tool matched to the firmware codename.
